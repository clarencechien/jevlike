# Handoff tw3 — 地名正規化：主場偏差是「語言」造成的，還是「地名」造成的？換成中立地名能不能消掉？（2026-11-21，跑前寫死；已跑，結果 `results/tw3-place-names.md`；只在 `tw` 線）

接 `docs/handoff-tw2-decision-apis.md`（結果 `results/tw2-decision-apis.md`）。**不合併 `main`**。

## 為什麼要測

tw2 量到：用爭議雙方自己的語言問同一句話，三家商用 decision API 在 11 個爭議裡有 8–10 個會往「那個語言的一方」偏。
我們 26B 的偏差，先翻成英文再判大多能消掉，**只有地名本身帶立場的消不掉**：
- 獨島／竹島：韓文 − 日文差距 1.25；先翻英文後仍有 1.18（日文版翻成英文還是「Takeshima」）。
- 南海：越南文 − 簡中 0.86；先翻英文後 0.66（簡中版翻成英文是「Huangyan Island」）。

但 tw2 裡語言和地名是綁在一起的：韓文一定寫「독도」、日文一定寫「竹島」。所以還不知道兩件事：
1. 偏差有多少來自**地名**、多少來自**語言**？
2. 把地名換成**中立叫法**（Liancourt Rocks、Scarborough Shoal、聯合國用的「Falkland Islands (Malvinas)」），偏差會不會消失？上線能不能靠「先翻英文＋地名對照表」處理這類內容？

## 0. 規則

- 同 tw2：跑前寫死門檻，跑完照門檻填三選一；預測錯照實寫。只送公開陳述，沒有產線資料。金鑰只從環境變數讀（`or_key`、`gemini_key`）。
- 模型、呼叫方式、指標全部沿用 tw2：
  - 五個模型：微軟 1.1、微軟 1.0、Gemini Decision 1、我們的 26B（prod 臂）、Clef。
  - 程式：`bench/tw2_api.py`、`bench/tw_script.py`。
  - 指標：Index、主場偏差、翻面、item bootstrap 區間。
  - 判定：tw2 的「有問題／沒問題／不確定」，以及讀得懂檢查（中性題 P真−P假 ≥ 0.8）。
- **讀不懂的照舊不判**：26B 在 tw2 讀不懂南海那組簡中（中性題 P真−P假 0.24–0.50）。所以 26B 的南海：
  - 原語言部分只算越南文、菲律賓文內部的地名效應，不算語言效應，也不判 H2。
  - 上線做法（E2）走英文，照常判。
- **原始寫法不重跑**：tw2 已有的格子（韓文＋독도、日文＋竹島、英文＋「Dokdo (Takeshima)」……）直接沿用 tw2 的讀數，只跑新的格子。
- 結果放 `results/tw3-place-names.md`、`results/tw3.json`、`results/modal/tw3/`。

## 1. E0：不用新跑，先從 tw2 的資料拆一次（南海）

tw2 南海的 4 對陳述裡，「九段線」「2016 仲裁」兩對**沒有任何地名**，「黃岩島／Scarborough」「南沙／Spratly」兩對有。
用 tw2 已有的讀數，分開算兩組的主場偏差（越南文、菲律賓文各對簡中）：
- 沒地名那組的偏差 ≈ 純語言效應。
- 有地名那組的偏差減掉沒地名那組 ≈ 地名的額外效應。

每組只有 2 對，區間會很寬，只當描述，不判門檻；用來對照 E1 的結果。

## 2. E1：語言 × 地名，交叉設計

三個地名有爭議的爭議，每種語言都把同一句話配上三種地名，其他字不動：

| 爭議 | 地名臂 | 韓／日／中／越／菲／西 等各語言的寫法（英文形式） |
|---|---|---|
| 獨島／竹島 | X 方叫法 | Dokdo（韓 독도、日 独島（トクト）） |
| | Y 方叫法 | Takeshima（韓 다케시마、日 竹島） |
| | 中立 | Liancourt Rocks（韓 리앙쿠르 암초、日 リアンクール岩礁） |
| 南海：黃岩島 | X 方叫法 | Bajo de Masinloc（菲律賓的叫法） |
| | Y 方叫法 | Huangyan Island（中 黄岩岛） |
| | 中立 | Scarborough Shoal |
| 南海：南沙 | X 方叫法 | 該語言國家的叫法：越 Trường Sa、菲 Kalayaan；簡中與英文用越南的 Truong Sa |
| | Y 方叫法 | Nansha Islands（中 南沙群岛） |
| | 中立 | Spratly Islands |
| 福克蘭／馬爾維納斯 | X 方叫法 | Falkland Islands（西 Islas Falkland） |
| | Y 方叫法 | Malvinas（西 Islas Malvinas） |
| | 中立（聯合國雙名） | Falkland Islands (Malvinas)（西 Islas Malvinas (Falkland)） |

語言沿用 tw2：獨島 ko／ja／en，南海 zh_cn／vi／fil／en（只換有地名的兩對），福克蘭 en／es。

**產生方式**（`bench/tw3_build.py`）：
- 從 tw2 的翻譯（`data/tw2/translations/`）出發，用每種語言的地名對照表做字串替換。
- 對照表由 Gemini 3.1 Pro 給出各語言的通行寫法，人工確認後寫進 `data/tw3/names.json`。
- assert：
  - 每句裡原地名恰好出現預期次數。
  - 替換後除了地名以外逐字相同。
  - 韓文助詞：三個地名都以母音結尾，`는／를` 不用改。
  - 西班牙文冠詞與單複數照原句。
- 英文「Dokdo (Takeshima)」原本就是雙名；E1 的英文另外補「只寫 Dokdo」「只寫 Takeshima」「只寫 Liancourt Rocks」三格。

**盲審**：另一個 agent 看全部替換後的句子，確認只換了地名、文法正確、對照表的寫法是該語言的通行寫法。不合理率 > 5% 就修正重生。

**筆數**：
- 新格子：獨島 7 格、南海 12 格（兩對 × 語言 × 地名，扣掉 tw2 已有的）、福克蘭 4 格。
- 每格 = 該爭議受影響的陳述數 × 3 種問法，約 650 個 job。
- 五個模型共約 3,300 次讀取。

## 3. E2：上線做法——先翻英文，再套地名對照表

- 拿 tw2 已有的「先翻英文」文字（`data/tw2/jobs.jsonl` 的 `alt.pivot`）。
- 用一張英文地名對照表把各方叫法換成中立叫法：Takeshima／Dokdo → the Liancourt Rocks；Huangyan Island／Bajo de Masinloc → Scarborough Shoal；Nansha／Truong Sa／Kalayaan → the Spratly Islands；Malvinas → the Falkland Islands (Malvinas)。
- 這是程式可以直接做的前處理。
- 臂：
  - **pivot**：只翻英文，不換地名。26B 已有 tw2 讀數；三家 API 與 Clef 補跑。
  - **pivot＋names**：翻英文再換地名。五個模型都跑。
- 範圍：獨島、南海、福克蘭三個爭議，各語言 × 4 對（含沒地名的對）× 3 種問法。

## 4. 指標與門檻

每個模型 × 每個爭議（區間用 4 對（南海 E1 只有 2 對）的 item bootstrap）：

- **地名效應** E_name：對每種語言，Index(X 方叫法) − Index(Y 方叫法)，再對語言平均。正值 = 寫成哪一方的叫法就往哪一方偏。
- **語言效應** E_lang：對每種地名臂，Index(X 方語言) − Index(Y 方語言)，再對地名臂平均。
- **H1 地名主導**：E_name ≥ E_lang ＋ 0.10，且 E_name 區間下界 > 0。
- **H2 原語言＋中立地名能消掉**：
  - 中立地名下的主場偏差 Index(X 方語言, 中立) − Index(Y 方語言, 中立)，照 tw2 判法：「沒問題」＝ 消掉。
  - 另報「減半」：中立地名下的偏差 ≤ tw2 原始偏差的一半。
- **H3 先翻英文＋地名對照表可以上線**：pivot＋names 的主場偏差「沒問題」且翻面 ≤ 2／24。
  - 只看 26B（我們會用的）：三個爭議都過 →「可上線」。
  - 三家 API 照實報。

**決定規則**（寫進 tw 線的報告，不動 `main`）：
- H3 對 26B 三個都過 → 政治／主權內容若要自動判斷，前處理寫成「統一字形 → 翻英文 → 地名正規化」，附對照表。
- H3 沒過 → 這類內容不進自動判斷，一律轉人。地名之外還有東西帶立場，tw3 的錯誤分析要指出是什麼。
- H1 成立 → 報告寫「主場偏差大部分是地名造成的」，就算不翻譯也應該先換地名。H1 不成立 → 寫「語言本身就帶偏差，換地名只是一部分」。

## 5. 預測（跑前寫）

- **E0（南海）**：沒地名那兩對的偏差仍有 0.3–0.6，所以語言本身就有效應；有地名那兩對再多 0.2–0.4。
- **E1 獨島**：H1 成立，地名效應 0.6–1.0、語言效應 0.2–0.4。原語言＋中立地名，偏差減半但仍「有問題」（剩 0.2–0.4）。
- **E1 南海**：H1 對黃岩島成立；南沙不明顯，因為越南文、菲律賓文版本原本就有一邊用中立名。
- **E1 福克蘭**：H1 不成立。地名效應 < 0.15，語言效應 0.3 左右，英文對西班牙文本身就偏。
- **E2 26B**：pivot＋names 在福克蘭「沒問題」（tw2 只翻英文已經 0.07）；獨島、南海降到 0.1–0.3，「不確定」或「有問題」。H3 不過。
- **E2 三家 API**：只翻英文就能消掉一半以上；加地名對照表再降一些，但 Gemini 與微軟 1.0 在南海仍「有問題」。
- 微軟 1.1 和 26B 的地名效應方向、大小接近（同底模）。

## 一句話結論（三選一，跑完填）

**選第二句**：地名是一部分，但不夠。原語言換成中立地名，26B 獨島偏差 1.25 → 0.35，仍「有問題」；語言效應（0.76）比地名效應（0.50）大。先翻英文＋地名對照表後，26B 獨島、福克蘭與南海「菲 − 簡中」都「沒問題」，但南海「越 − 簡中」0.17 [−0.00, 0.39]「不確定」，H3 不過。這類內容不進自動判斷。詳見 `results/tw3-place-names.md`。

原本的三個選項：

- 「地名主導、而且可以處理：主場偏差有 X 來自地名；先翻英文＋地名對照表後，26B 三個爭議都沒問題（差距 ≤ Y），政治內容可以照這個前處理自動判斷。」
- 「地名是一部分，但不夠：換成中立地名偏差降 X，仍有 Y 來自語言本身；這類內容不進自動判斷。」
- 「地名不是主因：地名效應 < 0.10，偏差幾乎都來自語言；地名正規化沒有用。」
