# tw3 — 地名正規化：主場偏差來自語言還是地名？換成中立地名能不能消掉？（2026-11-21）

計劃與門檻：`docs/handoff-tw3-place-names.md`（跑前寫死，commit `4b650f6`）。只在 `tw` 線，不合併 `main`。
完整表格：`results/tw3-place-names-tables.md`（`bench/analyze_tw3.py` 產生）；數字：`results/tw3.json`；原始回應：`results/modal/tw3/`。
資料：`data/tw3/`（地名對照表 `names.json`、`jobs.jsonl`、盲審用的 `SPOTCHECK.md`）。只送公開陳述，沒有產線資料。

## 一句話

**地名是一部分，但不夠。**
- 同一種語言只把地名換成中立叫法：
  - 我們 26B 的獨島偏差從 1.25 降到 0.35，但仍「有問題」。
  - 五個模型、三個爭議，沒有一格消掉。
- 在原語言裡，語言本身的偏差多半比地名大：26B 的獨島，語言效應 0.76，地名效應 0.50。

**先翻英文、再套地名對照表，大部分偏差都消失了，但 26B 沒有三個爭議全過。**
- 獨島 1.18 → −0.11，福克蘭 0.01 → −0.03，都「沒問題」。
- 南海「越南文 vs 簡中」0.67 → 0.17 [−0.00, 0.39]，判「不確定」。
- 剩下的偏差集中在「2016 仲裁」那一對。兩邊翻成英文的句子寫法不同；那一對本來就沒有地名。

照決定規則：**政治／主權內容不進自動判斷，一律轉人**。地名正規化本身有效，只是還不足以讓這類內容自動判斷。

（handoff 三句中選第二句。）

## 2. 上線做法：先翻英文，再套地名對照表（E2）

對照表（`data/tw3/names.json` 的 `pivot_en_normalizer`）：
- Dokdo／Takeshima → the Liancourt Rocks
- Huangyan Island／Bajo de Masinloc → Scarborough Shoal
- Nansha／Truong Sa／Kalayaan → the Spratly Islands
- Malvinas → the Falkland Islands (Malvinas)

主場偏差／翻面（/24）。H3 通過 = 「沒問題」且翻面 ≤ 2，該爭議每個比較都要過。

| 模型 | 獨島 韓−日：只翻英文 → ＋對照表 | 南海 越−簡中 | 南海 菲−簡中 | 福克蘭 英−西 | H3 |
|---|---|---|---|---|---|
| 微軟 1.1 | 0.49/10 → −0.17/3 ✗ | 0.14/4 → −0.07/1 ✓ | 0.12/6 → −0.10/3 ✗ | 0.30/3 → 0.02/0 ✓ | ✗ |

| **Gemini D1** | 0.14/1 → −0.08/2 ✓ | 0.19/5 → 0.02/0 ✓ | 0.21/6 → −0.02/0 ✓ | 0.30/4 → 0.04/0 ✓ | **✓ 三個都過** |
| **26B（我們）** | **1.18/14 → −0.11/1 ✓** | **0.67/9 → 0.17/2 不確定** | 0.40/7 → −0.11/1 ✓ | 0.01/3 → −0.03/0 ✓ | **✗（南海）** |
| Clef | 0.10/2 → −0.18/5 ✗ | 0.65/10 → 0.17/6 不確定 | 0.62/8 → 0.02/3 不確定 | 0.45/6 → −0.05/0 ✓ | ✗ |

- **地名對照表把「只翻英文」剩下的偏差大致清掉了**。26B 的獨島從 1.18 降到 −0.11，南海從 0.67／0.40 降到 0.17／−0.11。五個模型的福克蘭都歸零。
- **剩下的不是地名。** 26B 南海「越 − 簡中」剩的 0.17，幾乎全在「2016 仲裁」那一對，單對 +0.52：
  - 越南文翻回英文是「The 2016 arbitral ruling on the South China Sea is …」。
  - 簡中翻回英文是「The ruling of the 2016 South China Sea arbitration case is …」。
  - 兩句內容相同，只差寫法。26B 對這一對本來就接近 0.5，寫法一變答案就跟著變。
  - 「菲 − 簡中」同一對是 −0.45，方向相反。可見這是機器翻譯寫法帶來的雜訊，不是主場偏差。
- **反向的偏差**：微軟 1.1、26B、Clef 在獨島 pivot＋names 後是負的（−0.11 到 −0.18），即日文來源的句子反而比較挺韓國。
  - 26B 的負值來自「1905 編入」（−0.25）和「領土地位」（−0.16）兩對。日文翻回英文是「The incorporation of Takeshima by Japan in 1905」，韓文翻回是「Japan's incorporation of Dokdo in 1905」，又是寫法差。
  - 計劃的判法只看主場方向，所以 26B 的 −0.11 [−0.21, −0.01] 照規則判「沒問題」。若改用 tw2 塞爾維亞文那種「兩個方向都算」的判法會是「有問題」；H3 照樣不過，結論不變。

## 4. 決定

照計劃的決定規則：
- **H3 對 26B 沒有三個都過 → 政治／主權內容不進自動判斷，一律轉人。** 產線題不受影響，這條規則只影響政治內容。
- **H1 不成立 → 「語言本身就帶偏差，換地名只是一部分」。** 只換地名、不翻譯，偏差剩一半左右，不夠用。
- 如果以後要重新考慮讓這類內容自動判斷，該修的是翻譯步驟：同一句話不論從哪種語言翻回來，英文寫法要一致。地名對照表本身已經有用。重開要另寫計劃，不在這輪放寬。
- 附帶：Gemini Decision 1 是唯一「翻英文＋對照表」三個爭議都過的。這輪的翻譯也是 Gemini 做的，可能同源，見 tw2 的備註。

## 5. 偏離計劃之處

- **盲審**：另一個 agent 審全部 184 句新句子，2 句有錯（1.1%，低於 5% 門檻），已在送出前修正。
  - 英文正規化把「Japan's 1905 incorporation of the Liancourt Rocks was …」的 was 誤改成 were，已拿掉這條規則。
  - 另建議菲律賓文用連寫的通行形式，已改成 Pulong Huangyan、Kapuluang Kalayaan、Kapuluang Nansha。
  - 簡中的「长沙群岛」是越南叫法的通行譯名，但和長沙市同字，保留未改。
- **地名寫法**：
  - 日文的獨島用「独島」，不是計劃寫的「独島（トクト）」，照 Gemini 給的通行寫法。
  - 西班牙文雙名照聯合國西文慣例寫成「Islas Malvinas (Falkland)」。
- **福克蘭英文 X 格重跑**：tw2 的英文句首是小寫「the Falkland Islands are …」（產生器的小 bug）。tw3 從範本重產並修正大小寫，所以這格重跑；tw2 原句另列為 `orig_lc`。兩者幾乎一樣（26B 0.80 vs 0.82），大小寫沒有影響。
- **只翻英文那一臂**：計劃說 26B 沿用 tw2；實際 26B 也一起重跑，順便當重跑檢查。
  - 結果：同文字 216 筆，平均差 0.019，最大差 0.58，9 筆跨 0.5。
  - 跨 0.5 的大多原本就接近 0.5，最大的一筆是日文來源「inherent-Y」第二問法，0.98 → 0.40。
  - 這和 tw 的 G4 一樣：目前伺服器設定（一次四題、重用快取）不保證每次相同。26B 在 H3 的「翻面 ≤ 2/24」接近它自己的重跑雜訊，判讀要記得這點。表內 26B 用 tw3 這次的讀數。
- **南海兩對分開算**（黃岩島、南沙各自的 H1）：每格只有 1 對，沒有區間，未判。
- **成本**：
  - OpenRouter（微軟兩版 2,064 次）$0.0034。
  - Gemini（1,032 次判斷＋1 次對照表）在免費額度內。
  - Modal（26B L4、Clef L40S 各一個容器，約 2 分鐘）約 $0.1。
  - 合計約 $0.1。
