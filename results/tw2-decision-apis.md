## 一句話

**新模型沒修好。** 三個新的商用 decision 模型看到簡體都還是往北京偏：
- 84 題翻 17–20 題。
- 微軟 1.1（底模就是我們的 Gemma 26B）把翻面從 35 題降到 17 題，算部分繼承。
- 先轉繁就全部消失。

**別的爭議也會出事，而且更普遍。** 用爭議雙方自己的語言問，三家 API 在 11 個爭議裡有 8–10 個出現「用哪一方的語言問就往哪一方偏」。
- 最嚴重的是獨島／竹島：同一句話韓文問和日文問，13–17／24 個答案相反。
- 其次是南海（中文對越南文、菲律賓文）和克里米亞（烏克蘭文對俄文）。

**先翻成英文再判，能消掉我們 26B 大部分的偏差，但地名本身就帶立場的消不掉。** 翻成英文後仍是「Takeshima」或「Huangyan Island」，模型照樣往那一方偏。

這張表的讀法：
- **三家新 API 在幾乎每個爭議都有主場偏差。** 換語言的 6 個爭議，微軟 1.1 和 Gemini 全部出事，微軟 1.0 出事 5 個。
  論文只測了台灣，這次看到這是**多語輸入的一般性問題**，不是台灣特有。
- **地名就是立場**：
  - 獨島／竹島在每個模型、每種處理下都是最大的偏差，先翻成英文也一樣（1.18）。翻成英文後，日文版變成「Takeshima is Japanese territory」，地名本身就告訴模型該站哪邊。
  - 南海同理：簡中版翻成英文是「Huangyan Island」，越南文和菲律賓文版是「Scarborough Shoal／Bajo de Masinloc」，先翻英文只降一部分（0.86 → 0.66）。
  - 地名換了，等於事實換了，這不是翻譯能解決的。
- **我們的 26B 在中國敏感題上反而沒事**：新疆、西藏、香港、六四的繁簡差距都 ≤ 0.10，跟 tw 的 E2 一致。
  - 三家 API 在新疆、西藏有 0.12–0.32 的差距。
  - Clef（Qwen 系）在四題裡有三題超過 0.3。
- **我們的 26B 對塞爾維亞文的兩種字母很敏感**（0.51、9 格翻面），我預測不會。統一成拉丁字母就消失（0.03）。
  所以 tw 的「先轉繁」要擴大成「先統一字形」。
- **「先翻英文」對 26B 有效**：科索沃 0.70 → −0.01、克里米亞 0.43 → −0.01、福克蘭 0.35 → 0.07、北賽普勒斯 1.09 → 0.27、喀什米爾（印地文那邊）也歸零。
  地名帶立場的兩個（獨島、南海）例外。
- **讀不懂的語言**：26B 在烏爾都文、土耳其文，和南海那組簡中（中性題 P真−P假 0.24–0.50）不判。Clef 讀不懂土耳其文。三家 API 每種語言都讀得懂。

## 判定（對 handoff §2、§3.3）

- **A**：三家都 G1「有問題」、G2 ✗、G3 ✓；G4 微軟 1.1 ✓、微軟 1.0 ✗、Gemini ✓。**沒有一家「修好了」**；「先轉繁」三家都歸零。
  A-繼承：微軟 1.1 對我們 26B r = 0.75（< 0.8），判「部分繼承」。
- **B**：微軟 1.1、微軟 1.0、Gemini、Clef 都在 ≥ 3 個可判的爭議上有主場偏差。照決定規則：**它們的多語輸入在政治／主權內容上不可信，判斷前要先把輸入統一成單一語言**。但先翻英文消不掉地名帶的立場。
- **26B**：
  - B1 塞爾維亞文字母「有問題」→ 「先轉繁」擴大成「先統一字形」。
  - B2 有問題，而「先翻英文」能消掉大部分 → 寫成可選的前處理。翻譯有成本，產線題用不到，不寫成必做。

## 對 jevlike 的意思

1. **產線題不受影響**。tw 量過產線題換簡體有 98.5% 答案不變，這輪沒有新的產線結論。
2. **輸入一律先統一字形**：中文轉繁、塞爾維亞文統一成同一種字母。這一步便宜、無害。
3. 如果 decision API 被拿去判斷政治、主權、輿情內容，**任何一家（含微軟、Google 的新模型）都不能直接吃多語輸入**。
   - 先翻成單一語言能消掉大部分偏差。
   - 地名本身帶立場的消不掉：要嘛不讓這類內容進自動判斷，要嘛把地名正規化成中立叫法再判（沒驗證過）。
4. 換到微軟 1.1 或 Gemini Decision 1 不會比我們好在這件事上：台灣題它們翻得比我們少，但新疆、西藏、科索沃（阿爾巴尼亞文對塞爾維亞文）、克里米亞它們一樣偏或更偏。

## 偏離計劃之處

- **Modal 中途撞到花費上限**，B 的 26B 與 Clef 晚開跑。使用者調高後，26B 三個臂與 Clef 改成四個容器平行跑。數字不受影響。
- **中性題判定有 bug，已修正**：產生器用「pair id 開頭是 n」判斷中性題，把克里米亞的 `now`、香港的 `nsl`、南海的 `ninedash`、北賽普勒斯的 `north`、六四的 `nature` 誤標成中性，第一次分析少算了這幾對。
  改成只認 `n1`／`n2` 後重建 `jobs.jsonl`。job id 不變，已送出的回應全部沿用，不用重跑。
- **翻譯盲審**：另一個 agent 審 408 句陳述與 102 個問句，0 個重大問題、15 個小問題，原檔 `data/tw2/translation_review.json`。有兩點影響解讀：
  - 喀什米爾的烏爾都文把「不可分割的一部分」譯成較弱的「必要的一部分」，可能讓印地文對烏爾都文的差距略為放大。
  - 香港題把 2020 年《香港國安法》譯成《國家安全法》，雙方用詞相同，不影響對稱。
- **翻譯模型**：用 Gemini 3.1 Pro（AI Studio），一般生成模型，不是受測的 Gemini Decision 1。翻譯與它可能有同源偏好，Gemini Decision 1 的 B 結果要記得這一點。
- **Gemini Decisions API 的特性**：是非題機率限制在 0.01–0.99；選擇題選項依 id 字母序排序後才評估，E5 的 6 種排列對它沒有作用。
- **E6 圖片題略過**（同 tw）。
- **成本**：
  - OpenRouter（微軟兩版，約 7,900 次）共 $0.018。
  - Gemini（約 3,900 次判斷＋約 130 次翻譯）在免費額度內。
  - Modal 四個容器約 $0.3。
  - 合計約 $0.35，遠低於預估的 $2。

## 後續：tw3 地名正規化（2026-11-21）

`results/tw3-place-names.md`。結論：
- 只把地名換成中立叫法不夠。26B 獨島 1.25 → 0.35，仍「有問題」；語言本身的偏差比地名大。
- 先翻英文再套地名對照表，26B 的獨島 1.18 → −0.11、南海 0.67 → 0.17。但南海一組仍「不確定」，剩下的來自機器翻譯的寫法差異，不是地名。
- 照規則：政治／主權內容不進自動判斷。
