**判讀**：

1. **不是 FP8 的問題**：同樣 bf16 權重、同一張 H100，SGLang 比 llama-server 低 2.6 點（A2 0.961 vs B2 0.935），兩者答案只有 95.9% 一致。差距來自後端（kernel、tokenizer、數值路徑），不是權重。
2. **不是併發或 RadixAttention 的問題**：B1 改成 workers=1（0.930）或關掉 radix cache（0.930）都和原本的 8 workers（0.931）一樣低。smoke 裡「同一 state 批次三題全答 B、單題答 C」的異常，三題的題幹多了「問題 i：」前綴，不是乾淨的對照；D0-w1 / D0-noradix 才是。
3. **SGLang 自己跑兩次也不一樣**：同一組 prompt、同一權重、同一卡，三次 B1 的答案兩兩只有 97.7% / 96.9% / 97.4% 一致（llama-server smoke 同 prompt 重跑，機率差在 1e-5 量級）。翻掉的 50 題（2,000 題中）**不是**邊界題：其中 32 題模型在原本那次給了 >0.9 的把握（翻掉題的把握中位數 0.97）。這對「拿信心當門檻」是壞消息：SGLang 上一題 97% 把握的答案，重跑可能變成另一個字母。
4. 結論：護欄未過是後端固有的，不是設定錯。依 `07-sglang-prereg.md`，速度門檻全過但護欄沒過 → **視同沒過**。
