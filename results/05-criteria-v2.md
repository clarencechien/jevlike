# 05 — 改寫判斷標準（v2）：警報急迫度與 SPC 處置

目的：v1 的 criteria 用形容詞描述邊界（「即將造成批量品質問題」「已連續多點」），模型在相鄰等級之間偏向較嚴重的一級。把邊界改成可數的規則（先數什麼、數到幾就是哪一級），看零樣本準確率能回多少。標準檔：`data/seeds/tasks_v2.json`；gold 不變。

## 錯誤分析（v1，200 筆）

| task | 主要混淆 | 例 |
|---|---|---|
| m_alarm_severity | B 盡快 → C 停線（27/38） | 「爐內無板、輸送帶已自動停止」「機台已自動停機且無法重啟」被判停線 |
| q_spc_action | D 呼叫 QE → C 停線複檢（28/37） | 「最後 3 點連續超出 LCL」「三個料號同時超限」被判單點停線複檢 |

## v2 寫法

- **急迫度**：先看是否「不良已產出／整線停或 ≥2 站在等／安全」→ 停線；再看「單站暫停或警告等級偏差」→ 盡快；其餘 → 不急。
- **SPC**：先數超限點數：≥2（連續、多站、多料號、複檢仍超）→ 呼叫 QE；=1 → 停線複檢；0 但有連串規則 → 抽檢；0 且無連串 → 持續監控。

急迫度改了兩輪（v2 → v2.1：v2 把「整線等料」和「SPI 警告」推錯邊，v2.1 把「≥2 站在等」歸停線、「警告等級 <10%」歸盡快）。

## 這算不算先射箭再畫靶

一半算。gold 沒動，改的是我們自己定的規格，這是正當的；但 v2 是看著這 200 筆的錯題改的，還改了兩輪，所以在同一批資料上的數字是樂觀值。補了一個 held-out：同模板換隨機種子產 140 筆模型沒看過的 easy 題（hard 60 筆無法重產、是看過的），凍結 v2.1 標準再跑一次，改善幅度幾乎相同（easy +7 / +13 個百分點）。這證明改善不是記住特定句子，但**沒有**證明對真實資料成立——那要等 200–500 筆真實警報／工單。

剩下的錯（v2.1 急迫度 23 筆）集中在兩種：AOI「NG 1 片、複判誤判」被判盡快（gold 不急）；英文「CONVEYOR STOPPED OVEN EMPTY」仍判停線。前者可再加一條「複判誤判 → 不急」，但那就是第三輪，留給真實資料。
