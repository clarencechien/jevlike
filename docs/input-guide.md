# 輸入準備指南：資料要怎麼整理再送進判斷層

依據：v23（`results/27-input-format.md`，合成資料、三個模型、六類題、每類 120 個事件 × 五種寫法）。
適用：機台 alarm、SPC、UPH／CT、工具呼叫這類「手上是 log 或結構資料」的判斷。人寫的訊息與工單（`x_*`）不在這份指南的範圍。
GB10 上要用真實 log 再驗一次（`docs/handoff-v23-input-format.md` §7）；驗完把差距補到本檔最後一節。

## 規則（照順序做）

### 1. 數字比較一律程式先算，寫成「結論＋數字」，原始值保留

模型沒拿到比較結果時會看表面線索：溫度低於上限仍判停線、廠務氣壓正常仍判環境、復歸次數沒超過仍判要派工，而且機率常是 0.99（v23：要比數字的題，26B 先算好 +8～+15 點，E4B +22，Clef +9；錯誤 86% 的機率 ≥ 0.95）。

| 要算的 | 寫法 |
|---|---|
| 量測值 vs 上下限 | `254°C，上限 245°C（與上限差 +9°C，超出上限：是）` |
| 比例、達成率 | `本班平均 781，目標 960（達成率 81.4%）` |
| 次數 vs 上限 | `本班已復歸 6 次，上限 5 次（與上限差 +1 次，超過上限：是）` |
| 容許範圍 | `供電 201 V，額定 220 V ±5%（容許範圍 209–231 V，偏差 -8.6%，在容許範圍內：否）` |
| 參數 vs 規格 | `temp_c=227，規格 230–250（參數在規格範圍內：否，低於下限，超出量 3）` |
| 代碼 | `alarm E-2107「VAC LO HD3」（代碼意思：第 3 頭吸嘴真空不足）` |

不要寫成判斷（「應停線」「嚴重」「需派工」）。那是模型的工作，寫進去就是把答案寫死，也就測不到模型。

### 2. 規則類計算給「結果」，不要給還要再比一次的中間數

- SPC：程式算好每條規則有沒有觸發，寫 `連續 7 點同側：否；連續 6 點單向：是；3 點中 2 點超過 2σ：否；超出管制界限：0 點`。
- 不要給 `"max_beyond_2sigma_in_3": 1` 這種計數。v23 裡 26B 把「有值」讀成「有觸發」，SPC 單點題從 91% 掉到 56%。同一個資訊寫成白話句子就全對。
- 欄位名用白話（`超出上限`、`在容許範圍內`），布林值配「是／否」。

### 3. 衍生欄位要覆蓋判斷標準的每一個面向，不然就都不給

只算一部分，模型會跟著被算的那部分走。v23 工具守門的角色題：括號裡列了「可復原、單線、在規格內」（全指向「詢問」），唯一決定答案的「呼叫者是操作員」沒寫，26B 從 100% 掉到 54%。
做法：對照題目的判斷標準逐條檢查。每一條都有對應的衍生欄位（角色權限也查表寫出 `操作員可改參數：否`），或者這一條改由程式規則處理。

### 4. 送進模型前拿掉無關欄位

event_id、uuid、時間戳、韌體版本、PLC 位址、操作員工號、主機名等，對判斷沒有用：
- 準確率：26B −3.6 點、E4B −3.5、Clef −1.7。
- token：+39%；延遲：+15%。
- 傷害集中在「要比對兩個欄位」的題（工具守門讀別條線 96% → 65%）。

做法：每類題維護一份**白名單欄位**，其他欄位一律丟掉。時間只在判斷需要時給（例如「已持續 7 分鐘」），而且給算好的持續時間，不給兩個時間戳。

### 5. 格式：預設用中文句子模板；JSON 也可以，但要驗

- 六類平均，JSON 與文字差不到 2 點。
- 單一類可差 5–13 點，方向不一：JSON 在 UPH、原始數列較好；文字在原因分類、派工、電壓、單站停機題較好。
- 三個模型最好的寫法都是「中文句子＋括號裡的衍生值」（T1 型）：26B 89.2%、E4B 82.2%、Clef 90.7%。
- 手上是 JSON log：用程式填句子模板，不要直接把 JSON 丟進去。
- 一定要用 JSON 的話：照第 1–4 條做，每一類在 GB10 上用真實資料比過再上線。

### 6. 模型不套的規則，用程式規則先擋

有些規則，衍生欄位寫得再清楚，模型也不套。下面兩例在五種寫法都只有約 50%：
- 跨線操作要拒絕：`影響線數 2` 寫明了，三個模型仍判「詢問」。
- 「超限＋爐內有板」對「超限＋已自動停止進板」。

這類規則放在模型前面，用程式判定。也可以改寫判斷標準再驗一次（v2 的做法）。v9「工具守門的範圍交給規則」的結論不變；參數超規格則可以靠第 1 條救回（80% → 100%）。

### 7. 信心值與門檻

- 先算好後 ECE 降一半（0.18–0.20 → 0.10–0.12），但仍偏有把握。
- 上線門檻照 `bench/thresholds.py` 用真實資料重新反推。
- 換了輸入寫法，就要重新反推門檻。

## 範例：同一則 alarm

原始 log（不要直接送）：
```json
{"event_id":"EV-20261105-693445","uuid":"8e92…","ts":"2026-11-05T14:23:13.347Z","fw":"RX-3.2.17","host":"smt-edge-28",
 "line":"SMT-L3","device":"R-03","zone":7,"temp_c":269,"limit_hi_c":255,"duration_min":7,"board_in_oven":true,"conveyor":"running"}
```

送進判斷層的 state（白名單欄位＋衍生，句子模板）：
```
SMT-L3 回焊爐 R-03 第 7 區溫度 269°C，上限 255°C（與上限差 +14°C，超出上限：是），此讀值已持續 7 分鐘；爐內有板，輸送帶運轉中
```

如果一定要 JSON：
```json
{"line":"SMT-L3","device":"R-03","zone":7,"temp_c":269,"limit_hi_c":255,"duration_min":7,"board_in_oven":true,"conveyor":"running",
 "超出上限":true,"與上限差_c":14}
```

## 實作提示

- 每類題一個 `render_<task>(event) -> str`。程式碼放在呼叫判斷層之前，跟 `decide/` 分開。
- 產生器 `data/v23/gen_v23.py` 的 `text(f, d)` 是可以照抄的雛形。它的 `FORBID` 清單用來檢查有沒有把答案寫進衍生值。
- 寫好後跑一次 twin 檢查：只改一個數字讓答案換，看模型有沒有跟著換。
